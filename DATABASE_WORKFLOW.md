# Работа с базой данных

## Основные команды

### Получить актуальный код и базу данных
```
make db-pull
```

### Обновить фикстуры из своей локальной базы и отправить в репозиторий
```
make db-push
```

### Только загрузить фикстуры в базу (без `git pull`)
```
make db-load
```

## Workflow

### Перед началом работы 
```
make db-pull
```

### Когда изменили базу и хотим поделиться

1. Предупреждаем в чате, чтобы другие пока не работали с базой 

2. Убеждаемся, что у нас есть все актуальные данные из удаленного репозитория
```
make db-pull
```

3. Отправляем изменения 
```
make db-push
```

4. Сообщаем в чат, что фикстуры обновлены

---

## Решение конфликтов

### Если при `make db-pull` или `git pull` возник конфликт:

1. Решаем конфликт в редакторе

2. В зависимости от типа конфликта:

**Если конфликт в фикстурах** (файл `fixtures/realestate_data.json`):
```
git add fixtures/realestate_data.json
git commit -m "Resolve fixture conflict"
```

**Если конфликт в коде** (файлы `models.py`, `views.py` и др.):
```
git add .
git commit -m "Resolve code conflicts"
```

3. Загружаем обновленные фикстуры в базу
```
make db-load
```

4. Проверяем, что всё работает
```
python manage.py runserver
```

### Важно:
Не надо делать `make db-pull` после решения конфликтов - это вызовет повторные конфликты. Используем только `make db-load`.

---

## Важные предупреждения

`make db-pull` обновляет весь код проекта:

- `git pull` - загружает все изменения кода (модели, представления, шаблоны, миграции)
- `python manage.py migrate` - применяет миграции базы данных  
- `python manage.py loaddata` - загружает актуальные данные из фикстур

**Внимание:** `make db-pull` полностью перезаписывает локальную базу данных. Все локальные данные будут удалены и заменены данными из фикстур.

---

## Когда делать и когда не делать `make db-pull`

### ДЕЛАТЬ
- перед началом работы
- когда коллега сказал "обнови фикстуры"
- когда нужны актуальные данные для тестирования

### НЕ ДЕЛАТЬ
- в середине работы над задачей
- если есть несохраненные данные в базе
- если есть незакоммиченные изменения в коде

---

## Подготовка к `make db-pull`

Перед выполнением `make db-pull`:

1. Коммитим все свои изменения в коде
2. Сохраняем важные данные из базы (если нужно)

---

## Резервное копирование базы данных

1. Создать резервную копию своих данных
```
python manage.py dumpdata --exclude=auth --exclude=contenttypes --exclude=sessions --indent=2 > my_backup.json
```

2. Восстановить данные из резервной копии
```
python manage.py loaddata my_backup.json
```
